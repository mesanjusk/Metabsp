# Packaging: PWA, Android APK, Windows

One codebase, three distributions. All three serve the same deployed web app, so a fix ships once
and reaches all of them — there is no second build to keep in step, and no app-store review between
a bug and its fix.

| | What the user gets | Built from | Needs a store? |
|---|---|---|---|
| **PWA** | Installs from the browser, home screen icon, offline page | Nothing — already live | No |
| **Android** | A real `.apk` / `.aab` (Trusted Web Activity) | `packaging/android/` | Only for Play Store |
| **Windows** | An `.exe` installer, Start-menu and desktop entry | `packaging/windows/` | No |

---

## 1. PWA — already shipped

Nothing to build. It is live wherever `nextjs/` is deployed.

The pieces, so they can be found when something breaks:

| File | What it does |
|---|---|
| `nextjs/public/manifest.webmanifest` | Name, icons, colours, start URL, shortcuts |
| `nextjs/public/sw.js` | Service worker — installability, cached shell, offline page |
| `nextjs/public/offline.html` | Shown when a navigation cannot reach the network |
| `nextjs/public/icons/*` | Generated by `npm run icons` from the brand mark |
| `nextjs/lib/ui/app/PwaProvider.jsx` | Registers the worker, offers the install prompt |
| `nextjs/app/layout.tsx` | `manifest`, `themeColor`, `viewport-fit=cover` |
| `nextjs/lib/http/securityHeaders.js` | `worker-src 'self'` — without it the worker is blocked |

Regenerate the icons after a change to the brand mark:

```bash
cd nextjs && npm run icons
```

**Verifying an install works:** open the deployed site in Chrome → DevTools → Application →
Manifest. "Installability" must report no errors, and Service Workers must show one activated.
If installability fails, it is almost always the CSP (`worker-src`) or a manifest icon 404.

## 2. Android APK — Trusted Web Activity via Bubblewrap

A TWA is a thin Android app that opens this origin full-screen with no browser UI. It needs no
JavaScript bridge, no second codebase, and it passes Play Store review as a normal app.

### Prerequisites (one machine, one time)

- JDK 17
- Android SDK command-line tools
- `npm i -g @bubblewrap/cli`

### Build

```bash
cd packaging/android

# 1. Point the config at the real host.
#    Replace REPLACE_WITH_PRODUCTION_HOST throughout twa-manifest.json first.

# 2. Generate the Android project from the live manifest.
bubblewrap init --manifest="https://YOUR_HOST/manifest.webmanifest"
#    Accept twa-manifest.json's values when prompted.

# 3. Build. Produces app-release-signed.apk and app-release-bundle.aab.
bubblewrap build
```

### Digital Asset Links — the step that is always skipped

Without this the app opens **with a browser address bar across the top**, which is the single most
common "why does my APK look like a website" report. Android checks that this origin vouches for
the app before it will hide that bar.

```bash
# Print the signing certificate's SHA-256 fingerprint.
keytool -list -v -keystore packaging/android/android.keystore -alias sanjusk
```

Copy the `SHA256:` value into `nextjs/public/.well-known/assetlinks.json`, using
`assetlinks.json.example` as the template, then deploy. Verify it is live and correct:

```
https://YOUR_HOST/.well-known/assetlinks.json
```

Google's own checker: <https://developers.google.com/digital-asset-links/tools/generator>

**Keep `android.keystore` and its passwords somewhere they cannot be lost.** Play Store will not
accept an update signed with a different key — ever. A lost key means a new listing and every
existing install stranded.

## 3. Windows — Electron shell

A thin Electron window over the same origin. It is a separate npm package on purpose: it is not in
the web app's workspace, has its own `node_modules`, and cannot affect the web build.

```bash
cd packaging/windows

# Point it at the real host — edit APP_URL in main.js, or pass it at build time.
npm install
SANJUSK_URL=https://YOUR_HOST npm run build      # → dist/SanjuSK Setup 1.0.0.exe
```

`npm start` runs it without packaging, which is the fast way to check a change.

What the shell adds over a browser tab: its own taskbar identity, a Start-menu and desktop entry, no
address bar, remembered window size, and external links (including Meta's sign-in flow) opening in
the user's real browser rather than trapping them inside the app window.

The renderer is sandboxed with `contextIsolation` on and no Node access, because it loads a remote
origin. The preload exposes one boolean and no IPC — see `preload.js` for why.

### The simpler Windows option

Edge and Chrome both offer **Install this site as an app** from the address bar, which produces a
real Windows app with a Start-menu entry from the PWA alone — no build, no installer to distribute.
For most customers this is enough. Build the Electron installer when you need something to hand
someone as a file, or a Microsoft Store listing.

## Before any of this ships

- [ ] Replace every `REPLACE_WITH_PRODUCTION_HOST` in `packaging/android/twa-manifest.json`
- [ ] Replace `REPLACE_WITH_PRODUCTION_HOST` in `packaging/windows/main.js` (or set `SANJUSK_URL`)
- [ ] Publish `nextjs/public/.well-known/assetlinks.json` with the real fingerprint
- [ ] Confirm the deployed site passes Chrome's installability check
- [ ] Back up `android.keystore` off the build machine
